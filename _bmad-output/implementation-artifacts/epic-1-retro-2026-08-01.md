## Challenges and lessons

### Clean local state can hide clean-runner defects

Generated declarations in the developer checkout masked build-before-typecheck
ordering. Future CI edits need validation from a clean checkout, not only the
active workspace.

### A pinned-looking SHA is not sufficient evidence

An annotated tag object and commits from different action repositories were
misassigned. Pin maintenance must verify that each SHA resolves in the named
repository and represents the intended release commit.

### Isolated source and installed dependencies are distinct planes

Branch/PR analysis correctly isolates source in a worktree, while dependencies
remain installed in the invoking checkout. Bare package resolution must use a
mirrored containing-file location in that dependency plane, then classify the
result as verified external: no traversal, code execution, or absolute-path
emission.

### Cross-platform tests must assert the actual platform contract

Windows long-path integration cases cannot pretend to exercise the same branch
on Linux. Platform-pure seams should run everywhere; OS-specific integrations
should be explicitly conditional. Linux also exposed a real `ENOTDIR`
reclamation ordering defect for prefixed file residue.

### Literal fake credentials have delivery consequences

Even intentionally fake values can trip host push protection when present in
history. Security fixtures should construct recognizable values at runtime or
live in deliberately governed fixture surfaces.
